# Thesis Reader — 论文阅读与领域探索助手

## 1、Skill 简介

这是一个帮助科研人员快速阅读论文、分析研究领域、寻找相关文献的 Skill。通过 AI 自动解析论文内容，生成结构化的 HTML 分析报告，同时支持根据研究方向搜索并推荐相关论文，适合需要频繁追踪学术前沿的研究者使用。

---

## 2、使用场景

### 2.1 论文阅读场景

**场景：刚接触一个新研究方向**

- **之前遇到的问题**：导师给了一篇 20 页的英文论文，从头啃完需要好几天；即使读完也容易遗漏重点，不知道这篇论文在领域中的定位。
- **做出来后的效果**：上传 PDF 后，几分钟内生成摘要报告，核心方法、贡献、验证结果一目了然；再生成全文概览，快速掌握论文结构，决定是否值得深入阅读。

**场景：写文献综述**

- **之前遇到的问题**：需要在 Related Work 章节引用几十篇论文，手动整理每篇的核心贡献和与本文的关系非常耗时。
- **做出来后的效果**：一键生成 Related Work 分析报告，自动梳理引用脉络、方法对比、时间线，生成带 DOI 链接的引用表格。

### 2.2 领域探索场景

**场景：进入一个新领域，想找入门必读论文**

- **之前遇到的问题**：在 Google Scholar 搜关键词，出来几百篇，不知道从哪篇开始；找到论文后还要手动去 arXiv、作者主页找免费链接。
- **做出来后的效果**：描述研究领域和研究方向，AI 搜索并筛选核心论文，每篇提供约 100 字的研究成果简述和免费 DOI 链接，生成可直接阅读的 HTML 报告。

**场景：追踪某个研究组或方向的新工作**

- **之前遇到的问题**：想跟某个实验室的最新进展，需要定期去官网刷新，或者在 Google Scholar 上设提醒，但整理起来还是麻烦。
- **做出来后的效果**：通过论文搜索功能，按研究组或方向整理论文推荐列表，每篇附带研究概述，形成自己的知识库报告。

## 3、创作过程

### 3.1 需求拆解

整个 Skill 的设计遵循「**理解 → 分析 → 探索**」三阶段工作流：

| 阶段 | 功能模块 | 核心问题 |
|------|---------|---------|
| 理解 | 摘要报告 + 全文概览 | 这篇论文在做什么？ |
| 分析 | 引言 / 相关工作 / 方法 / 实验 / 讨论 | 怎么做？为什么这样做？效果如何？ |
| 探索 | 延伸阅读推荐 + **论文搜索（新）** | 还有哪些相关工作？领域内有哪些重要论文？ |

### 3.2 提示词示例（核心工作流）

#### 阶段一：全文总览
```
帮我分析论文 /path/to/paper.pdf，生成全文总述 HTML。
```

#### 阶段二：选择章节深入分析
```
帮我生成 Related Work 部分的 HTML 报告。
帮我生成 Method 章节的 HTML 报告。
```

#### 阶段三：领域探索（新功能）
```
我正在研究「可变形几何的仿真与渲染」，帮我找 10 篇左右的经典论文和近期重要工作，每篇附上 100 字左右的成果简述和免费阅读链接，生成 HTML 报告。
```

### 3.3 技术架构

- **核心引擎**：[html_generator.py](file:///Users/dorian/Documents/solo/Paper/paper_finder/html_generator.py) — Python 脚本，统一封装了 9 种报告的生成逻辑
- **数据结构**：使用 Python dataclass 定义结构化数据对象（PaperBasicInfo、SearchPaper、RelatedPaperItem 等），确保报告内容与样式解耦
- **输出格式**：纯 HTML 文件，无需服务端，直接在浏览器打开即可
- **UI 设计**：采用卡片式布局、彩色分类标签、侧边导航栏，支持多页面切换

## 4、使用步骤

### 4.1 基础使用

**Step 1：** 在 Trae IDE 中调用 `thesis_reader` Skill。

**Step 2：** 提供论文内容（PDF 文件路径 / DOI / 论文标题）。

**Step 3：** 告知你需要的服务类型：
- 「帮我生成全文总述」
- 「帮我分析 Related Work」
- 「我研究的是 XX 方向，帮我找相关论文」

### 4.2 论文搜索功能使用

当你需要根据研究领域搜索论文时：

```
描述：我要研究 [你的研究方向]，比如"3D 服装仿真与物理模拟"
↓
AI 自动搜索该领域内的核心论文
↓
整理成带分组的 HTML 报告（经典方法 / 现代方法 / 应用案例等）
↓
每篇论文包含：标题、作者/年份/会议、约 100 字成果简述、免费 DOI 链接
↓
可直接在浏览器打开，点击链接跳转免费阅读
```

### 4.3 典型操作流程

```
用户上传 PDF
    ↓
生成「全文总述」→ 快速判断是否值得深入阅读
    ↓
根据需要选择章节 → 生成「Related Work」/「Method」/「Experiments」等报告
    ↓
想扩展阅读 → 生成「延伸阅读」推荐（同研究组 / 互补方法 / 应用案例）
    ↓
进入新领域 → 使用「论文搜索」功能，按方向找论文，生成研究报告
```

## 7、总结与思考

### 这个 Skill 目前最满意的地方

- **结构化输出**：将非结构化的论文内容转化为统一的 HTML 报告格式，视觉一致性好，浏览效率高。
- **参数驱动设计**：每个报告函数接收 dataclass 对象，而非硬编码内容，泛化能力强，可以适配任何论文。
- **DOI 链接自动附上**：阅读论文最麻烦的一步就是找免费原文，现在每篇推荐论文都直接带链接，点击即达。

### 后续还想怎么优化

- **PDF 自动上传识别**：目前需要用户手动提供 PDF 路径，后续希望能直接拖拽上传，自动解析。
- **引用关系图谱**：在 Related Work 报告中加入引用关系可视化图谱，更直观地展示论文之间的继承/对立关系。
- **文献管理集成**：生成的报告能导出为 BibTeX 格式，方便直接复制到论文写作中。

### 希望别人怎么体验或给我什么建议

- 建议先从一篇自己熟悉的论文开始测试，对比 AI 生成的分析是否准确，再判断能否信任用于陌生领域。
- 如果发现某些章节的分析有明显遗漏或错误，欢迎反馈具体论文和位置，方便迭代优化。
- 论文搜索功能目前依赖 AI 对领域的理解能力，如果搜索结果不够精准，可以尝试更具体地描述研究方向（如加上方法名、应用场景等关键词）。
